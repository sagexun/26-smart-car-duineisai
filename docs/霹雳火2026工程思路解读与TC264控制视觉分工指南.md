## 0. 一句话总览（先看数据流）

2026 工程是一个标准的两层控制架构：**内环速度 PI + 外环转向 PD（差速）**，视觉只负责输出一个"偏差值"。

```
摄像头320×240
   │ 缩放160×120灰度
   ▼
迷宫法扫线(八邻域种子生长) ──► 左右边线 left_line / right_line (CCD像素)
   │ 逆透视 → IPS世界坐标、均值滤波、等距采样
   ▼
左右中线 center_line_l / center_line_r（边线向赛道内平移半车宽）
   │ 预瞄点(aim_distance=0.55m)纯跟踪
   ▼
★ image_bias（循迹偏差，限幅 ±20）★ ←──── 视觉队友的唯一核心输出
   │
   ▼
┌─────────────────────────────────────────────────┐
│ 控制侧（你负责）                                   │
│  速度决策 base_speed（按元素类型加减速）             │
│  转向环 10ms：Fuzzy_PD(image_bias) → 差速目标      │
│      encoder_L_wish / encoder_R_wish              │
│  速度环 2ms：增量式 PI(编码器实际 vs 目标) → PWM     │
│      → 电机 → 编码器 → 反馈回速度环                  │
└─────────────────────────────────────────────────┘
```

**核心结论：**
1. **视觉队友做的一切工作的最终结果 = 一个数 `image_bias`（±20 的 float/int）**；
2. **你（控制）要做的循迹 = 读这个数 → 转向环算差速 → 速度环跟速度**；
3. 两代平台（2026龙芯 / TC264）的**控制结构完全一致**，只是写法（CPP类封装 vs C函数）和参数不同。

## 1. 2026 工程与 TC264 的平台差异（先对齐认知）

| 项目 | 霹雳火2026（龙芯2K0300） | 你的 TC264（2025例程） |
|---|---|---|
| 系统 | LoongArch64 + Linux，应用层 CPP | 英飞凌 TC264 双核 MCU，裸机 C |
| 图像处理位置 | 主循环逐帧（`main.cpp` while） | CPU1 主循环（`cpu1_main.c` `Image_Process()`） |
| 速度环 | 定时器 2ms（`motor_callback`） | CPU0 PIT 2ms 置标志，主循环执行 `Motor_control()` |
| 转向环 | 定时器 10ms（`turn_callback`） | CPU0 PIT 8ms（`cc60_pit_ch1_isr` → `turn_pid()`） |
| 传感器 | 5ms IMU+激光；20ms 模型推理 | 无 IMU/模型则跳过，或挂陀螺仪 |
| 调试 | 逐飞助手（TCP 8888，图像+8通道示波器+在线PID） | VOFA+/串口助手 + 例程自带在线调参协议 |
| 编码器 | 1024线，2ms 累加计数，二阶低通滤波 | 同，2ms 计数，二阶滞后滤波 |
| 差速系数 | 内侧减速 0.95 / 外侧加速 0.10 | 内侧减速 0.90 / 外侧加速 0.15 |

> 结论：**2026 工程 = 2025 TC264 例程的"思路升级版"**。你手里 2025 例程的 `motorL_pid()` / `turn_pid()` 骨架可以直接用，再吸收 2026 的改进点（死区补偿、反接制动、偏差限幅、不对称差速）。

## 2. 视觉侧思路（队友负责，你也要懂，才能对接口）

2026 工程视觉链路（`ImageBin2026/ImageProcess2026.cpp` 的 `ImageProcessGrew2026()`，当前 `USE_BIN=0` 走灰度迷宫法）：

### 2.1 巡线五步

1. **迷宫法扫线**（`ImageGrew2026/ImageFindSeed2026.cpp` 的 `BaLinYuSaoXian` / `find_maze_lines`）：
   - 把赛道看成迷宫：白色=赛道外（墙），黑色=赛道内（通道）；
   - 从图像**底部中心**向左右水平扫描找边界种子（差比和算法）；
   - 从种子出发用**左手/右手八邻域生长**沿边线向上"走迷宫"，得到左右边线点集 `left_line / right_line`（CCD 像素坐标，`l_line_count / r_line_count` 为有效点数）。
2. **逆透视**（`EdgeLinePerspective`）：CCD 像素 → IPS 世界坐标（用单应矩阵 `change_un_Mat`）。作用：消除近大远小，让后面的"等距采样/预瞄"在真实尺度下进行。
3. **滤波 + 等距采样**：`BlurPoints`（均值滤波去毛刺）→ `ResamplePoints`（按 `SAMPLE_DIST × PIXEL_PER_METER` 等物理间距重采样，后续索引=距离）。
4. **中线生成**（`track_leftline / track_rightline`）：把左右边线各自向赛道内平移 **TRACK_WIDTH/2**（半车宽）得到两条"可行中心线" `center_line_l / center_line_r`。哪条有效用哪条（`track_type`：边线点数>2 才算有效，默认右线）。
5. **预瞄偏差**（`ImageConversion.cpp` 的 `GetAnchorPointBias`）：
   - 从车底中心点 `(cx=80, cy=120)` 出发，沿中线找**预瞄距离 aim_distance=0.55m** 处的点；
   - 用**纯跟踪（Pure Pursuit）**公式算等效转角：
     ```
     dx = center_line[aim].X - cx
     Ackerman_angle = -atan(2·0.2·dx / dn²)   // 0.2=轴距(m)
     pure_angle = Ackerman_angle / π × 180 / 2.4
     image_bias = pure_angle（限幅 ±20）
     ```
   - **符号语义（必须写进接口文档）**：
     - `image_bias > 0` → 中线在车体**左侧** → 需要**左打方向**；
     - `image_bias < 0` → 中线在车体**右侧** → 需要**右打方向**；
     - `image_bias = 0` → 车正对中线。

### 2.2 元素识别与速度决策（视觉→控制的第二个接口）

- 2026 用**流程表驱动**：`process_status[] = {4,2,3,6,1,1,1,1,5}`（斑马线发车→右环岛→路障→左环岛→十字×4→斑马线停车），每个元素一个状态机（`ImageBin2026/*.cpp`：十字、环岛、路障、斑马线、坡道）。
- 检测结果写入 `g_ProcessFlags`（弯道/环岛/十字/斑马线/坡道/路障/起点标志），视觉侧再据此调用 `Speed_Decision2026()` 更新 `base_speed`（直道+20、弯道-15、环岛-12、路障+10、坡道-20/-30、模型-30）。

### 2.3 图牌识别 + 自主绕行（2026 赛题，TC264 视规则取舍）

- `Model.cpp`：NCNN 推理，64×64 输入，识别红色图牌类别（Carr/Item/Weap/Tele 等）；
- `ImageDetectModel2026.cpp` 的 `BlackRect_StateMachine`：Detect→Cut→**YAW**（用 IMU 角度闭环把车头转到目标角）→**TRACK**（切回边线循迹）→Finish；
- **对控制侧的影响**：YAW 阶段要 `g_yaw_active=1`（允许内轮反转）、切阶段前调 `MotorDriver_ResetSpeedPID()` 清掉速度环积分。

> **给队友的提示**：以上视觉链路里，TC264 上没有 OpenCV/NCNN 也能做——迷宫法扫线、逆透视（单应矩阵手算）、中线、预瞄偏差都是纯 C 可写的定点/浮点运算，2025 例程里就有 `Image_Process()` 的完整模板。

## 3. 控制侧思路（你的核心）—— 2026 工程怎么写的

### 3.1 定时器调度（main.cpp）

| 定时器 | 周期 | 回调 | 干的事 |
|---|---|---|---|
| `motor_timer` | 2ms | `motor_callback` | 读编码器 → 左右轮**增量式速度 PI** → 输出 PWM |
| `turn_timer` | 10ms | `turn_callback` | 读 `image_bias`（或绕行YAW误差）→ **转向环** → 差速目标 |
| `sensor_timer` | 5ms | `sensor_callback` | IMU 角度积分 + 激光测距 |
| `model_timer` | 20ms | `model_callback` | 模型推理（绕行用） |

**注意：转向环 10ms 算"目标速度"，速度环 2ms 追目标。外环慢、内环快，这是标准做法。**

### 3.2 速度环：增量式 PI（`driver/Motor.cpp`）

```cpp
// 全局参数：motor_pid = {Kp=100, Ki=5, Kd=0}  ← 速度环只用 PI
// PWM 限幅：±9500（SPEED_PWM_MAX/MIN）

int16_t MotorDriver_LeftPidControl(int16_t encoderTrue, int16_t encoderWish)
{
    int16_t i_out = 0;
    s_left_error = encoderWish - encoderTrue;
    i_out = motor_pid.Ki * s_left_error;

    // 增量式核心：pwm += Kp·Δe + Ki·e
    s_left_pwm += motor_pid.Kp * (s_left_error - s_left_lastError) + i_out;
    s_left_lastError = s_left_error;

    // 输出限幅 ±9500
    if (s_left_pwm >  SPEED_PWM_MAX) s_left_pwm = SPEED_PWM_MAX;
    if (s_left_pwm <  SPEED_PWM_MIN) s_left_pwm = SPEED_PWM_MIN;

    // 反接制动：目标≤0 且实际≤0 时不允许反转（YAW 绕行阶段跳过）
    if (!g_yaw_active && encoderWish <= 0 && encoderTrue <= 0 && s_left_pwm < 0)
        s_left_pwm = 0;

    // 死区补偿：起步时 PI 输出太小(<800)直接拉到 800，克服电机死区
    if (encoderWish > 0 && encoderTrue < ENCODER_START_THRESHOLD &&
        s_left_pwm > 0 && s_left_pwm < DEADZONE_PWM)
        s_left_pwm = DEADZONE_PWM;

    new_pwm_left = s_left_pwm;
    return s_left_pwm;
}
// 右轮完全对称（独立 static 状态）
```

**2026 相对 2025 的三个改进**（TC264 上建议都吸收）：
1. **死区补偿** `DEADZONE_PWM=800`：解决起步"给目标速度但电机不动"；
2. **反接制动**：正常巡线时目标≤0 就不让 PWM 变负，防止差速把内轮打成反转乱窜；绕行时打开 `g_yaw_active` 允许内轮反转原地旋转；
3. **状态重置** `MotorDriver_ResetSpeedPID()`：切换差速模式（如绕行 YAW）前清零累积 PWM，防止输出跳变。

### 3.3 转向环：模糊 PD → 差速（`driver/Motor.cpp` 的 `TurnControlNew`）

```cpp
// 全局参数：turn_pid_new = {Kp=1.52, Ki=0, Kd=10.4}
// 输入 bias：平时=image_bias；绕行YAW时=IMU角度误差×YAW_BIAS_GAIN

void MotorDriver_TurnControlNew(float bias)
{
    static float last_error = 0.0f;
    float error = bias;
    float Kp = turn_pid_new.Kp;
    float Kd = turn_pid_new.Kd;

    // 模糊增益调度：按偏差 E 和偏差变化率 EC 动态调 Kp/Kd
    Kp = Fuzzy_P(error, (error - last_error), Kp);   // 系数 0.90~1.30 倍
    Kd = Fuzzy_D(error, (error - last_error), Kd);   // 系数 0.85~1.35 倍
    float ec = error - last_error;
    if (ec > 3.0f)  ec = 3.0f;                        // EC 限幅
    if (ec < -3.0f) ec = -3.0f;

    float pid_val = (Kp * error + Kd * ec) / 20.0f;   // 归一化到差速系数
    last_error = error;

    if (pid_val > 0.0f) {   // 需要左转：左轮减速，右轮微加速
        encoder_left_wish  = (int16_t)((1.0f - pid_val * 0.95f) * base_speed);
        encoder_right_wish = (int16_t)((1.0f + pid_val * 0.10f) * base_speed);
        if (encoder_left_wish < 0) encoder_left_wish = 0;
    } else {                // 需要右转：右轮减速，左轮微加速
        float radian = -pid_val;
        encoder_right_wish = (int16_t)((1.0f - radian * 0.95f) * base_speed);
        encoder_left_wish  = (int16_t)((1.0f + radian * 0.10f) * base_speed);
        if (encoder_right_wish < 0) encoder_right_wish = 0;
    }
}
```

**差速思路**（和 2025 的 `xishu_down/xishu_up` 一个道理，2026 把内/外系数改成 0.95/0.10）：
- **内侧轮大减速**（0.95），**外侧轮小加速**（0.10）——减速为主、加速为辅，保速度、防甩尾；
- 内轮目标速度 **钳到 ≥0**：防止大偏差时内轮反转变"原地打转"；
- `pid_val` 除以 20 是把 PD 输出归一化到"差速比例"量级（配合 image_bias ±20）。

### 3.4 模糊 PID（`FuzzyPID.cpp`）—— 增益调度

- **动机**：直道偏差小，Kp 太大会抖动；急弯偏差大，Kp 太小切弯。所以按 (E, EC) 查 7×7 规则表动态缩放基础 Kp/Kd。
- **实现**：非线性论域（E：±3 内密集、±16 外稀疏；EC：±1.2 内密集）、O(1) 查表、取小-加权平均解模糊、纯 float。
- **系数**：P 输出 = 基础值 × {0.90,0.95,1.00,1.03,1.10,1.20,1.30}；D 输出 = 基础值 × {0.85,0.92,0.98,1.03,1.10,1.18,1.35}。
- **语义**：大偏差+同向变化率（入弯）→ 放开 D（允许快打）；大偏差+反向变化率（出弯）→ 加大 D（防回摆）；零偏差附近 → D 最大（直道稳）。

> TC264 移植时若想从简：第一步可以**不要模糊**，直接 `pid_val = (Kp*error + Kd*ec)/20`，先跑通再上模糊。2025 例程的 `FUZZYPID.c` 可以直接抄。

### 3.5 速度决策与 S 曲线

- `base_speed` 由视觉元素检测决定（`Speed_Decision2026(Plan_Speed)`），`Speed_Plan()` 做 **Jerk 限幅 S 曲线**（加速步长 1.15/帧、减速 2.4/帧），避免速度突变。
- 出界保护 `OutProtect2026()`、停车 `Stop_flag`、起跑红色块检测都在主循环处理，控制侧只需**照抄结构**。

## 4. 在 TC264 上怎么写你的电机 PID（实操模板）

### 4.1 迁移对照表（2026 → 你的 TC264）

| 2026（龙芯） | 你的 TC264（2025例程位置） | 建议 |
|---|---|---|
| `motor_pid = {100, 5, 0}` | `Motor_Left/Right_PID`（`code/control.c` `PID_Init()`） | 以 2025 的 {70,3.5,0} 为起点 |
| `motor_callback` 2ms | `Motor_control()`（`code/Encoder.c`，2ms 标志调用） | 原样保留 |
| `MotorDriver_LeftPidControl` | `motorL_pid()`（`code/pid.c`） | 加上 2026 的死区补偿/反接制动 |
| `turn_pid_new = {1.52, 0, 10.4}` | `turn` {1.35, 0, 9.33} + `fuzzy_p=4.385/fuzzy_d=14.350` | 先用 2025 参数起步 |
| `TurnControlNew(bias)` | `turn_pid()`（`code/pid.c`，8ms） | **把 `ImageStatus.Det_True` 换成你的 `image_bias`** |
| `Fuzzy_P/D` 百分比调度 | `Fuzzy_P()/Fuzzy_D()` 绝对调度 | 用 2025 现成的 |
| `base_speed` 元素加减速 | `Basic_Speed` + `Speed_Decision()` | 原样 |

### 4.2 TC264 速度环推荐代码（吸收 2026 改进）

```c
// code/pid.c —— 左轮增量式速度 PI（右轮对称，独立 static）
#define ENCODER_START_THRESHOLD  10   // 启动阈值：编码器实际<10 视为静止
#define DEADZONE_PWM             800  // 电机死区补偿 PWM

static int16 last_error_L = 0, pwm_L = 0;

int16 motorL_pid(pid_param_t pid, int16 enco_true, int16 enco_wish)
{
    int16 error = enco_wish - enco_true;

    // I 项限幅（防积分饱和）：单步增量 ≤ Ki*65
    float i_out = pid.Ki * error;
    if (i_out >  pid.Ki * 65) i_out =  pid.Ki * 65;
    if (i_out < -pid.Ki * 65) i_out = -pid.Ki * 65;

    // 增量式 PI：pwm += Kp·Δe + Ki·e
    pwm_L += pid.Kp * (error - last_error_L) + i_out;
    last_error_L = error;

    // 输出限幅（实际最大占空比 PWM_MAX=8000）
    if (pwm_L >  PWM_MAX) pwm_L =  PWM_MAX;
    if (pwm_L < -PWM_MAX) pwm_L = -PWM_MAX;

    // ★ 2026 改进1：反接制动 —— 目标≤0 且实际≤0 时禁止反转
    if (enco_wish <= 0 && enco_true <= 0 && pwm_L < 0) pwm_L = 0;

    // ★ 2026 改进2：死区补偿 —— 起步阶段 PI 输出不够时直接给死区 PWM
    if (enco_wish > 0 && enco_true < ENCODER_START_THRESHOLD &&
        pwm_L > 0 && pwm_L < DEADZONE_PWM) {
        pwm_L = DEADZONE_PWM;
    }

    return pwm_L;
}
```

### 4.3 TC264 转向环推荐代码（读 image_bias → 差速目标）

```c
// code/pid.c —— 转向环（8ms），视觉偏差 image_bias → 左右轮目标速度
// 参数：turn.Kp=1.35 / turn.Kd=9.33（起步），模糊基准 fuzzy_p/fuzzy_d 照 2025
extern int16 image_bias;          // ★ 视觉队友写的全局偏差
extern int16 Basic_Speed;         // 基础速度（速度决策给出）
extern int16 ENCO_Wish_L, ENCO_Wish_R;

void turn_pid(void)
{
    int16 error = image_bias;                  // 读视觉偏差（±20）
    static int16 last_error = 0;
    float ec = (float)(error - last_error);    // 偏差变化率
    float Kp = Fuzzy_P(error, ec);             // 模糊 PD（TC264 版接口）
    float Kd = Fuzzy_D(error, ec);
    float pid_val = (Kp * error + Kd * ec) / 20.0f;   // 归一化

    if (pid_val > 0.0f) {                      // 偏差>0：需左转
        ENCO_Wish_L = (int16)((1.0f - pid_val * 0.95f) * Basic_Speed);
        ENCO_Wish_R = (int16)((1.0f + pid_val * 0.10f) * Basic_Speed);
        if (ENCO_Wish_L < 0) ENCO_Wish_L = 0;
    } else {                                   // 偏差<0：需右转
        float radian = -pid_val;
        ENCO_Wish_R = (int16)((1.0f - radian * 0.95f) * Basic_Speed);
        ENCO_Wish_L = (int16)((1.0f + radian * 0.10f) * Basic_Speed);
        if (ENCO_Wish_R < 0) ENCO_Wish_R = 0;
    }
    last_error = error;

    // 安全：未启动/出界/停车时目标清零（照 2025）
    if (Motor_Flag == 0 || go == 0) { ENCO_Wish_L = 0; ENCO_Wish_R = 0; }
}
```

### 4.4 调参顺序（内环 → 外环，单变量）

```
第0步 确认反馈：编码器方向（反了 P 越大越飞车）、滤波、量纲（2×编码器计数）
第1步 死区补偿：架空车轮，给 ENCO_Wish=100，确认 PWM 能起来（DEADZONE_PWM 是否触发）
第2步 只调 P（Ki=0）：直道固定目标速度，Kp 从 10 起加，直到"跟得上、不震荡"
      （2025参考 70；换车架/电池必须重调）
第3步 加 I：从 0.5 起加，消除静差（2025参考 3.5）；I 过头会低频振荡
第4步 检查限幅：PWM_MAX 是否给满（追不上先查 PWM 饱和，别盲目加 P）
第5步 左右轮分开调（EL/ER 单独给目标），消除机械跑偏
第6步 合起来跑：先固定 image_bias=0 确认直行，再放开偏差调转向环 Kp/Kd
第7步 转向环模糊：先固定 Kp/Kd 跑弯道，再调 fuzzy_p/fuzzy_d 基准
第8步 固话参数：串口在线调参只是临时生效，调好写回 PID_Init() 重新烧录
```

**具体在线调参指令**（2025 例程自带，VOFA+ 直发）：`P1=70!`（左Kp）、`I1=3.5!`（左Ki）、`P2=...`（右Kp）、`EL=100!`（左目标）、`ER=100!`（右目标）、`sd=1!`（启动）。详见《霹雳火2025电机PID调参参考.md》§5。

## 5. 如何用视觉队友传来的偏差值完成循迹（★ 接口契约 ★）

这是你们两人合作的**核心协议**。建议直接复制这张表作为接口文档，双方签字确认。

### 5.1 接口变量定义

| 变量 | 类型 | 谁写 | 含义 | 符号约定 | 范围 | 更新频率 | 无效/异常值 |
|---|---|---|---|---|---|---|---|
| `image_bias` | int16/float | 视觉写、控制读 | 预瞄点循迹偏差 | **>0 需左转（中线在车左）<0 需右转（中线在车右）** | ±20 | 每帧（≥80Hz） | 丢线时置 0 或保持上一帧（双方约定） |
| `left_line_count` / `right_line_count` | uint8 | 视觉写、控制读 | 左右边线有效点数 | — | 0~120 | 每帧 | 0 = 丢线 |
| `track_type` | uint8 | 视觉写 | 当前跟踪哪条中线 | 0=左线 1=右线 | 0/1 | 每帧 | — |
| `element_flag` | 位标志 | 视觉写 | 当前元素类型 | 弯道/环岛/十字/斑马线/坡道/路障 | 位图 | 每帧 | — |
| `stop_request` | uint8 | 视觉写 | 请求停车（斑马线停/出界） | 1=停 | 0/1 | 每帧 | — |
| （可选）`center_line[]` | 点列 | 视觉写 | 中线点（IPS坐标） | — | — | 每帧 | 供控制侧高级策略用 |

### 5.2 符号约定（最重要，必须实测确认）

- 上表 `image_bias>0 → 左转` 是 2026 工程的语义；**你们落地时必须以实车测试为准**：
  1. 车静止摆在中线**右侧**（即中线在车**左**），看视觉输出 `image_bias` 是否为正；
  2. 反了就把 `image_bias` 取负（`image_bias = -image_bias;`），或改转向环里差速的加减号——**只改一处，不要两边都改**。
- 量纲约定：`image_bias` 是"归一化转角需求"（±20），不是像素数、不是 PWM。**视觉队友不要在输出里混入像素偏差**，控制侧按 ±20 的协议调参数。

### 5.3 控制侧消费代码（TC264，接 4.3 的 `turn_pid`）

```c
// 主循环/8ms 中断里，先取一帧"同源数据"再控制：
void control_tick(void)
{
    // 1. 读视觉数据（同帧读取，避免偏差和标志错位）
    int16 bias  = image_bias;
    uint8 lost  = (left_line_count < 2 && right_line_count < 2); // 双边丢线

    // 2. 丢线保护：双边丢线时保持上一帧偏差并降速（或停车），不猛打方向
    if (lost) {
        if (bias > 0) bias = last_bias; else bias = -last_bias;  // 示例：保持方向
        Basic_Speed = Basic_Speed * 0.6;
    } else {
        last_bias = bias;
    }

    // 3. 喂给转向环 → 差速目标
    turn_pid();          // 内部读 image_bias（或传参 bias）

    // 4. 速度环 2ms 追目标（motorL_pid/motorR_pid）——已在上文
    // 5. 停车/出界：stop_request==1 → ENCO_Wish_L/R=0
}
```

**要点**：
- **同帧性**：`image_bias` 和 `line_count/element_flag` 必须是同一帧算出来的（视觉侧用一个结构体打包，控制侧一次性读出），否则丢线判断和偏差会错位；
- **丢线行为是协议的一部分**：建议默认"丢线=保持上一帧偏差 + 降速"，由视觉侧在 `line_count` 上给出判据；
- **起步逻辑**：视觉给出 `Start_Flag`（起跑块移走）后才允许 `ENCO_Wish` 非零，控制侧起步用 `acc_speed` 慢加速，别直接跳目标速度。

### 5.4 安全保护（控制侧兜底，不依赖视觉）

照 2026 抄三点：出界保护（跑出赛道外停车）、`Rush_time` 超时停车、急停后电机 PWM 清零 + 关负压。**控制侧必须有独立的兜底逻辑，视觉烂了不能飞车。**

## 6. 视觉队友需要做哪些准备（交付清单）

### 6.1 必须交付（接口层面）

1. **接口文档**（就是 5.1 那张表）：变量名、类型、含义、符号、范围、频率、无效值——**先书面确认再写代码**；
2. **`image_bias` 的计算**：边线提取 → 逆透视 → 中线 → 预瞄偏差，至少先跑通"简化版"（如直接用图像底边行左右边线中点减图像中心，也够起步），再升级预瞄；
3. **边线点数 + 丢线判据**：`left/right_line_count` 的语义和阈值（<2 算丢线），并约定丢线时 `image_bias` 的行为；
4. **元素标志**：弯道/环岛/十字/斑马线/坡道/路障的检测结果，供你（控制）做速度决策——第一版可以只输出"直道/弯道/停车"三态；
5. **同帧打包**：偏差+计数+标志放进同一个结构体，一次写完（TC264 上注意 float 写入非原子，建议用 int16 或关中断拷贝）。

### 6.2 标定清单（视觉自己要做，需要你配合确认）

| 项目 | 说明 |
|---|---|
| 相机安装 | 俯仰角固定后**不许动**，动了逆透视矩阵全失效 |
| 逆透视矩阵 | 标一次存 Flash/数组，换场地只调曝光和阈值 |
| 车宽 TRACK_WIDTH / 轴距 | 影响中线平移量和预瞄公式，数值给你一份 |
| 预瞄距离 aim_distance | 0.55m 起步，直道可加大、弯道减小（后续联合调） |
| 图像压缩尺寸 | 160×120 起步，保证一帧处理 <20ms、帧率 ≥80fps |
| 丢线阈值 | 按赛道宽度实测 |

### 6.3 调试工具准备

- **TC264 侧**：VOFA+（FireWater 协议）看波形，字段建议 `go, bias, wishL, wishR, encL, encR`——你俩都能实时看到 `image_bias` 曲线是否合理；
- 例程自带在线调参协议（`P1=70!` 等），你改 PID、视觉侧配合看 `bias` 波形；
- 有条件再上逐飞助手（TCP 上位机）看图像+边线叠加，定位丢线根因。

### 6.4 联调流程（建议里程碑，按顺序验收）

```
M1 静态验证：车静止，人把车摆在中线左/右，确认 image_bias 数值与符号正确（±20 内）
M2 直线巡线：低速（如 ENCO_Wish=60）跑直道，偏差收敛、不画龙
M3 弯道巡线：左右弯各跑通，转向环 Kp/Kd 有手感
M4 丢线演练：人为遮挡摄像头，确认丢线行为符合协议（不飞车）
M5 元素联调：斑马线停、十字、环岛逐个过
M6 速度提升：按"内环→外环→速度"顺序提升，每轮只改一个参数
```

### 6.5 如果做 2026 赛题的"图牌识别+绕行"

- 需要你（控制）配合：绕行 YAW 阶段 `g_yaw_active=1`（允许内轮反转）、切阶段前重置速度环积分、YAW 期间偏差来源切到 IMU 角度误差；
- TC264 无 IMU 时可先做"定角度绕行"（时间/距离开环），再考虑 IMU。

## 8. 避坑清单（两代平台通用）

1. **编码器方向错了，P 越大越飞车**——调参第一步永远是确认反馈方向；
2. **追不上 ≠ P 小**——先查 PWM_MAX 是否饱和、目标速度是否超过机械上限；
3. **内环不跟手，外环调得再好也白搭**——先速度环后转向环，不要跳步；
4. **image_bias 符号必须实车确认**——接口文档写的符号只是 2026 工程的约定，换相机/换安装位置可能反；
5. **丢线处理是协议**——视觉不报丢线，控制侧也要有"偏差突变/双边丢线→降速保持"的兜底；
6. **同帧性**——偏差和标志必须同一帧，否则元素切换瞬间会打架；
7. **参数固化**——在线调参掉电丢失，调好写回初始化函数；
8. **相机安装角固定**——动了相机，逆透视矩阵和偏差全废；
9. **滤波与 P 的 trade-off**——滤波越重波形越平但滞后越大；速度环（内环）不需要 D，对噪声敏感；
10. **起步别跳目标速度**——用加速段（acc_speed / S曲线）平滑起步，防起步窜车。
