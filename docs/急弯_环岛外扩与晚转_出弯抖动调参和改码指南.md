## 1. 先给你最直接的答案

| 你的问题 | 优先处理什么 | 具体调哪里 |
| --- | --- | --- |
| 急弯不丝滑 | 先查误差是否跳、差速是否突然打满，再调整转向增益 | `Motor.c` 的 `Turn_PID_Control()`；`image.c` 的 `find_mid_line_lookahead_error()` |
| 环岛路线过内 | 分清当前是从内侧短边，还是外侧长边生成中线 | 短边：`RING_INSIDE_WIDTH` 加大；长边：`RING_FALLBACK_LONG_WIDTH` 减小 |
| 进入环岛过早转 | 准备阶段沿外侧边走，真正满足入环条件再切换 | `ring_try_one_side_mid()` 的状态 1 选边、偏移；然后调 `RING_S1_TOP_B` |
| 出弯进直道抖 | 先排除中线/前瞻跳变，再处理差速回正、轮速回升太突然 | 前瞻回退逻辑、转向 PD 的 D 项、差速指令变化率 |

**不要把三个问题都当成“P 不够大”，也不要把环岛所有偏移系数一起增大。**下面每个步骤都有生效条件。

## 2. 当前到底是哪套代码在控制小车

当前执行链是：

```text
CPU1 每处理一帧图像：
image_deal()
  → ring_process() 可能重写中线
  → find_mid_line_lookahead_error()
  → pid_error

CPU0：
每 20 ms：Turn_PID_Control() → 左右轮目标速度
每 10 ms：编码器测速 + 左右轮速度 PI → PWM
```

这是双电机差速转向。不要按照舵机角度去理解 `turn`。

### 2.2 先记录运行时参数，不要只看 PID 初始化值

`uart.c` 中 `NUM1.angle_p`、`NUM1.angle_d` 的源码默认值都是 0，但上位机可能已经改过。转向函数实际用的是：

```c
image_pid.Kp = NUM1.angle_p + 0.003f * error * error;
image_pid.Kd = NUM1.angle_d;
```

因此默认基础 P 为 0，不等于转向完全没有 P。左右轮速度 PI 也会由 `NUM1/NUM2` 同步，不能把 `pid.c` 中 `PID_CREATE(...)` 的初值当成运行中的最终值。

还有一个观测陷阱：`pid_sync_to_motor()` 会把 `image_pid.Kp` 再写回基础 P，现有串口又直接发送这个字段，所以显示出来的 Kp 未必是上一轮转向实际用过的 Kp。后面记录时应增加单独的 `turn_kp_used`，由转向计算处赋值，主循环只发送。

### 2.3 环岛参数总表

下面的“增大效果”只说明当前判断式中的直接作用，不代表越大越好。图像坐标中 **y 越小越远、越大越靠近车**。参数主要集中在 [image.c 的环岛参数区](<D:/ads/workspace 4+/Seekfree_TC264_Opensource_Library/code/image.c:8890>)。

#### 状态先看懂

| `ring_state` | 当前含义 | 主要动作 |
| ---: | --- | --- |
| 0 | 普通道路/等待识别 | 检测左右环岛特征；冷却期内不识别 |
| 1 | 已识别，准备入环 | 等短边先延伸到远处、再退回来；当前代码也可能提前重建中线 |
| 2 | 正式环内阶段 | 优先由短边按 `RING_INSIDE_WIDTH` 生成路线，计满固定帧数后进状态 3 |
| 3 | 等待出环 | 继续生成环内路线；满足出环条件并连续确认后回状态 0 |

#### 最常调的路线和入环参数

| 参数 | 当前值 | 生效阶段/意义 | 增大后的直接效果 | 针对你当前问题怎么试 |
| --- | ---: | --- | --- | --- |
| `IPM_CALIBRATED_LANE_WIDTH` | `30.0f` | 逆透视下的标定赛道宽，是几个偏移系数的基准 | 所有按比例计算的偏移一起变大 | 它属于几何标定，不拿来当普通调路线旋钮；先核对标定 |
| `RING_INSIDE_WIDTH` | `0.65 × W = 19.5` | 状态 2/3 由环岛内侧短边向赛道内生成路线 | 中线离内侧短边更远，通常向环岛外侧移动 | 确认本帧用短边时，先试 `0.65 → 0.70` |
| `RING_FALLBACK_LONG_WIDTH` | `0.75 × W = 22.5` | 用外侧长边保底时，向环岛内侧生成路线 | 中线从外边向岛内移动更多，路线通常更靠内 | 想外扩应反向调小，先试 `0.75 → 0.70` |
| `RING_S1_TOP_A` | `20` 行 | 状态 1 第一门：短边 `top < A`，连续确认后说明短边已延伸到远处 | 条件更容易、更早满足 | 当前不优先改；先解决状态 1 路线提前偏内 |
| `RING_S1_TOP_B` | `35` 行 | 状态 1 第二门：第一门通过后，短边 `top > B` 才进状态 2 | 短边要退得更靠近车才满足，通常会晚转 | 先试 `35 → 40 → 45`，每次只加 5 |
| `RING_CONFIRM_FRAMES` | `3` 帧 | 环岛识别、状态 1 两个门槛、状态 3 十字锁存共同使用的确认帧数 | 多处判断都变慢，但抗单帧误判更强 | 不用它单独解决“晚转”；需要时另设入环专用确认帧数 |
| `RING_INSIDE_MS` | `3000 ms` | 状态 2 保持时长 | 状态 2 更久，进入状态 3 更晚 | 它不控制开始转弯时间；不要拿它解决入环过早 |
| `RING_FRAME_MS` | `20 ms` | 把毫秒参数换算成帧数的假定帧周期 | 派生帧数变少 | 相机处理并非稳定 50 FPS 时会产生时间偏差；不是调车旋钮 |
| `RING_INSIDE_FRAMES` | `150` 帧 | `3000 / 20` 的派生值 | 跟随上面两个参数变化 | 源码旧注释写 `300` 已过期，实际宏运算结果是 150 |
| `RING_S1_TIMEOUT_MS` | `5000 ms` | 状态 1 长时间未成功入环时复位 | 允许在准备状态等更久 | 只处理超时，不负责让车晚一点转 |
| `RING_COOLDOWN_MS` | `5000 ms` | 超时或出环后，暂时禁止再次识别 | 同一地点更不容易重复识别，同时更晚恢复检测 | 一般先保留 |
| `RING_COOLDOWN_FRAMES` | `250` 帧 | `5000 / 20` 的派生值 | 跟随上面两个参数变化 | 源码旧注释写 `300` 已过期，实际宏运算结果是 250 |
| `RING_APPROACH_LONG_WIDTH` | **当前源码没有**；本文建议 `0.50 × W` | 建议新增，仅供状态 1 沿外侧长边走正常半宽 | 值越大，准备阶段越向岛内靠 | 用于第 4.2 节的“识别后先沿外侧走”；不要与环内偏移混用 |

所以你当前最值得先调的只有四类：状态 1 的路线来源、`RING_S1_TOP_B`、`RING_INSIDE_WIDTH`、`RING_FALLBACK_LONG_WIDTH`。其余参数先用于解释日志，不要一股脑全改。

## 3. 环岛过内：到底增大哪个偏移

### 3.1 当前两个偏移，方向相反

在 `image.c` 里搜索：

```c
#define IPM_CALIBRATED_LANE_WIDTH 30.0f
#define RING_INSIDE_WIDTH        (IPM_CALIBRATED_LANE_WIDTH * 0.65f)
#define RING_FALLBACK_LONG_WIDTH (IPM_CALIBRATED_LANE_WIDTH * 0.75f)
```

当前算法锁定的 `ring_short_side` 是入环时的断边一侧。正常识别成立时，可以把短边理解为环岛内侧，另一条长边理解为外侧；首先用实际图像确认它确实跟到了预期边界。

`ring_mid_from_side()` 把边线逆透视后，沿指向赛道内的法线移动 `width`，再生成中线。所以：

| 补线来源 | 参数含义 | 想离环岛中心更远，应怎么调 |
| --- | --- | --- |
| 内侧短边 | 中线离内侧边的距离 | **增大** `RING_INSIDE_WIDTH`，例如 0.65 → 0.70 |
| 外侧长边 | 中线离外侧边、向环岛内移动的距离 | **减小** `RING_FALLBACK_LONG_WIDTH`，例如 0.75 → 0.70 |

左环、右环都按这个规则调，不用另加一个全局 `mid_line += N`。左右方向已经由边线法线处理了。

代码依据：[偏移参数](<D:/ads/workspace 4+/Seekfree_TC264_Opensource_Library/code/image.c:8954>)、[法线方向](<D:/ads/workspace 4+/Seekfree_TC264_Opensource_Library/code/image.c:8007>)、[偏移应用](<D:/ads/workspace 4+/Seekfree_TC264_Opensource_Library/code/image.c:9459>)。

### 3.2 先确定问题出在哪条补线分支

当前有两条主要路径：

1. **状态 2：**优先用短边；真实短边点数小于 `RING_MID_FALLBACK_ROWS = 5` 时才允许长边保底。注意这里检查的是点数，不是最终补出来的中线行数。
2. **状态 1、3：**`ring_try_one_side_mid()` 可能按两侧有效行数选更多的一侧，整帧重建中线。状态 1 当前也会这样做。

`ring_dbg_fb` 不能完整说明补线来源：状态 3 的提前接管可能直接返回，而且长边/普通中线保底都会用到这个标记。更可靠的是在“本帧最终接受哪条中线”的位置记录来源，例如 `NORMAL / SHORT / LONG / MIXED`；失败并恢复备份时也恢复来源标记。

不要只凭 `ring_state == 2` 就认为这一帧一定用了短边，也不要只凭 `ring_dbg_fb == 0` 就认定用了短边。

### 3.3 第一轮只改一个生效参数

如果确认环内主要使用短边，而且中线本身就贴内侧：

```c
/* 在 image.c 中替换原来的这条宏，不要再添加一个同名宏。 */
#define RING_INSIDE_WIDTH (IPM_CALIBRATED_LANE_WIDTH * 0.70f)
```

先只改 0.65 → 0.70。确实向外移动且两边都有余量，再单独考虑 0.75；不是要求最后一定调到 0.75。

如果偏内主要发生在长边保底期间：

```c
#define RING_FALLBACK_LONG_WIDTH (IPM_CALIBRATED_LANE_WIDTH * 0.70f)
```

从 0.75 → 0.70 比较，再决定是否试 0.65。**不要为了外扩把这个数改成 0.80，那会朝相反方向偏。**

这里每步 0.05 对应 1.5 个标定鸟瞰单位，不保证等于 1.5 厘米，也不对应各图像行固定的 1.5 像素。左右环都要看生成后的中线，特别是曲率较大时。

### 3.4 一个容易被忽略的问题：换边本身会跳路线

假设两条边确实相隔一个车道宽 W、局部平行，指向赛道内的法线共线且方向相反，那么：

```text
从短边算：离内侧 0.65 W
从长边算：离内侧约 (1 - 0.75) W = 0.25 W
```

两种来源对应的目标路径差了约 0.40 W。这是理想几何下的解释，不是对你的实际图像偏差的精确测量，但足以说明为什么换补线来源可能突然向里切。

长期应让“同一目标路线”从两侧计算时尽量一致。例如目标是离内侧 0.60 W，理想外侧距离应约为 0.40 W。**这不代表现在就把长边 0.75 猛改到 0.30/0.40。**先确认真实边界、标定尺度和两条候选中线，再逐步调整。

状态 3 的“哪边行数多就选哪边”也可能来回切。若日志证实频繁换边，可加选边滞回：候选边比当前边多出一定有效行、连续满足几帧才切；当前边完全不可用时立即允许回退。不要只延迟换边却继续使用已经失效的线。

## 4. 环岛过早转：先改准备阶段，再调入环门槛

### 4.1 当前为什么可能在状态 1 就提前转

当前 `ring_state1_fill_guard()` 实际只有：

```c
(void)ring_try_one_side_mid();
```

这个接管函数通常选有效行较多的一侧，选中长边时使用 **0.75 W** 的偏移。它不是“正常中线完全不够时才保底”，而是满足内部条件就可能重建整帧中线。状态 1 因此已经可能把目标路线往岛内拉。

所以，**先分清小车是在状态 1 就转了，还是状态 1 → 2 转换发生得太早。**两者改法不同。

位置：[状态 1 接管函数](<D:/ads/workspace 4+/Seekfree_TC264_Opensource_Library/code/image.c:9948>)、[状态 1 调用](<D:/ads/workspace 4+/Seekfree_TC264_Opensource_Library/code/image.c:11000>)。

### 4.2 推荐的小改法：状态 1 固定跟外侧长边，偏移先回到半车道

这一步借鉴两套参考工程的“准备阶段保持外侧跟线，满足入环条件后再切换”。它改变的是路线生成逻辑，不是硬锁电机直行；准备阶段仍然会正常纠偏。

**第一处：**在 `image.c` 环岛参数区新增：

```c
/* 仅用于准备入环阶段。环内偏移仍由原来的两个宏控制。 */
#define RING_APPROACH_LONG_WIDTH (IPM_CALIBRATED_LANE_WIDTH * 0.50f)
```

**第二处：**在 `ring_try_one_side_mid()` 中，替换原来决定 `many_side` 的整段 `if / else if / else`：

```c
if(ring_state == 1)
{
    /* 准备入环时固定外侧边，避免随两边点数来回换路线。 */
    many_side = RING_LONG_SIDE();
}
else if(rows_left == rows_right)
{
    many_side = ring_short_side;
}
else if(rows_left > rows_right)
{
    many_side = EDGE_LEFT;
}
else
{
    many_side = EDGE_RIGHT;
}
```

下面原有的 `few_side`、`rows_many` 赋值和素材不足检查继续保留。变量虽然叫 `many_side`，状态 1 现在表达的是“选用哪边”，不再保证它行数最多。

**第三处：**在同一函数里，替换原来的 `width = ...`：

```c
if(ring_state == 1)
{
    width = RING_APPROACH_LONG_WIDTH;
}
else
{
    width = (many_side == RING_LONG_SIDE())
          ? RING_FALLBACK_LONG_WIDTH
          : RING_INSIDE_WIDTH;
}
```

这样状态 1 从外侧走半车道，状态 2/3 仍分别按环内参数生成路线。长边素材不足、两边粘连或生成失败时，原函数仍可能放弃接管；因此这不是“无条件保证晚转”，要同时记录接管成功与否。

**第四处：**建议把状态 1 → 2 的切换收口到同一条处理路径。原来设置 `ring_state = 2` 后，下面仍会调用名为 `ring_state1_fill_guard()` 的函数。可以把成功切换的块改成：

```c
if(ring_confirm >= RING_CONFIRM_FRAMES)
{
    ring_state       = 2;
    ring_frames      = 0;
    ring_confirm     = 0;
    ring_relax_trace = 1;
    gocross          = 1;

    ring_apply_mid_inside();
    return;
}
```

其后原有的 `ring_state1_fill_guard(); return;` 保留，供“本帧仍在状态 1”时使用。当前 `ring_apply_mid_inside()` 定义在 `ring_process()` 前面，不需要凭空新增一套入环函数。爬线放宽仍从下一帧的 `image_deal()` 起生效。

以上四处作为一个逻辑改动检查；先保持原来的入环门槛和环内偏移，验证状态 1 的目标线变化。

### 4.3 如果确认是状态 2 进入太早，再改这个数

当前状态 1 的检查顺序是：

```text
短边最远点行号 < 20，连续确认
  → ring_started = 1
  → 再等短边最远点行号 > 35，连续确认
  → ring_state = 2
```

图像 y 越大越靠近车。因此在短边最远点随接近而退向图像底部的这段过程中，可以试：

```c
#define RING_S1_TOP_B 45   /* 原来 35；也可先试 40 */
```

建议 35 → 40 → 45，每次只改 5 行，看真正开始转入的位置是否后移。不是这个值越大越好；太大可能迟迟进不了状态 2、错过入口或触发状态 1 超时。

有个必须一起理解的边界：`ring_real_top()` 无点时返回 **127**，它也满足 `> 35`、`> 45`。如果过早切状态来自短边突然全丢，单纯增大 B 无效。若采用“可见几何位置”作为门槛，应把第二段条件改成下面这种有效性判断：

```c
/* 在 ring_process() 开头的局部变量区新增。 */
uint8 short_top;

/* 只替换状态 1 第二次检查的 if 条件及其前一行。 */
short_top = ring_real_top(short_side);
if(short_top != 127 && short_top > (uint8)RING_S1_TOP_B)
{
    /* 原来的 ring_confirm 自增逻辑。 */
}
else
{
    ring_confirm = 0;
}
```

这个判断会改变“完全丢边时允许入环”的行为，必须单独验证。有些入口确实要靠丢边特征入环，那就给丢边分支增加可靠的距离/其他特征门槛，不能把 127 当成一个真实角点坐标。

### 4.4 不建议靠这些参数实现晚转

| 参数/做法 | 为什么不优先这样调 |
| --- | --- |
| `RING_INSIDE_MS` 调大 | 它控制状态 2 持续多久；不会推迟状态 1 → 2 |
| `RING_ENTER_FRAMES` 调大 | 当前没被执行路径使用 |
| `RING_CONFIRM_FRAMES` 从 3 大幅增加 | 它被多个确认过程共享，也会影响识别和出环相关锁存；不只是入环延迟 |
| 检测到环岛后 `delay_ms(...)` | 会阻塞处理；车辆还在走，图像和控制不能停着等 |
| 全局把 `PROSPECT_LINE` 调大 | 普通急弯也会看近，可能解决了环岛早转，却让普通弯道反应晚 |

需要额外确认帧时，单独增加 `RING_ENTRY_CONFIRM_FRAMES`，只用于状态 1 的第二段检查。按处理帧计数的延迟会随实际帧率变化；50 FPS 下多 2 帧约 40 ms，车速 230 cm/s 时名义上已走约 9.2 cm，实际还取决于环岛中的轮速。

### 4.5 更进一步：借鉴 2026 的行驶距离门控

2026 的思路是：识别到入口后进入 `STRAIGHT_IN`，保持外侧跟线并累计里程，走到门槛再进入 `ENTERING`。它比固定等多少帧更适合速度会变化的情况。

你已有编码器累计数，可按当前测速换算系数估算前进距离：

```text
每个计数约 0.4412 × 26.80 / 1024 = 0.01155 cm
前进距离 ≈ (左轮新增计数 + 右轮新增计数) / 2 × 0.01155 cm
```

这仍依赖你车的编码器分辨率、传动比和轮周长是否标定正确。

建议结构如下，**这是设计伪代码，不是可直接粘贴的现成接口**：

```text
状态 1 的第二段几何条件连续确认通过：
    锁存“入口位置已确认”
    记录这一刻的里程，而不是每帧重记

保持外侧跟线：
    到达入口位置后再向前走 extra_entry_cm
    且当前仍有可用跟线数据 → 切状态 2
```

`extra_entry_cm` 可以从 0、3、5 cm 做低速比较，不照抄 2026 的 350 mm。复位环岛状态时清掉锁存和距离起点，并保留超时处理。计数在 CPU0 更新、图像状态在 CPU1：真正实现时要处理一致快照、数据可见性和计数回绕，不能把几个跨核变量加上 `volatile` 就认为完整了。

## 5. 急弯不丝滑：先看是不是“差速一下打满”

### 5.1 当前有很强的非线性

现在基础 P 为 P0 时，比例输出是：

```text
Kp = P0 + 0.003 × e²
P 输出 = P0 × e + 0.003 × e³
turn = 限幅((P 输出 + D 输出) / 150, -1, 1)
```

暂按 P0=0、D=0 举例：

| 误差 e，像素 | 动态 Kp | P 输出 | turn |
| ---: | ---: | ---: | ---: |
| 10 | 0.30 | 3.0 | 0.02 |
| 20 | 1.20 | 24.0 | 0.16 |
| 30 | 2.70 | 81.0 | 0.54 |
| 37 | 4.107 | 151.959 | 已被夹到 1 |
| 40 | 4.80 | 192.0 | 已被夹到 1 |

也就是“小误差时软，大误差时增长很快”。这不证明抖动一定由它引起，但如果误差在 25～40 像素之间跳，转向指令会变化得很明显。

位置：[实际转向计算](<D:/ads/workspace 4+/Seekfree_TC264_Opensource_Library/code/Motor.c:198>)。

### 5.2 先建立一个低速基准

在 `user/isr.c` 搜索这行：

```c
Turn_PID_Control(230.0f, 0.10f, 0.95f, 150.0f);
```

第一轮只把基础速度试为 180：

```c
Turn_PID_Control(180.0f, 0.10f, 0.95f, 150.0f);
```

如果低速明显顺畅，高速才乱，说明速度、跟线延迟或轮速响应的影响较大；如果低速也在同一位置猛跳，优先查中线和补线分支。

保持控制周期和编码器换算不变，不要通过改 PIT 周期来“变顺”。

### 5.3 给转向 P 一个更容易调的范围

如果波形确认差速经常突然打满，可在 `Motor.c` 中用下面的候选方案替换原 Kp 赋值：

```c
/* 放在 Motor.c 文件级宏区。以下只是低速探索起点。 */
#define TURN_KP_QUAD  0.001f
#define TURN_KP_MAX   5.0f

/* 在 Turn_PID_Control() 内替换原来的 Kp 赋值。 */
image_pid.Kp = Limit_float(
    0.0f,
    NUM1.angle_p + TURN_KP_QUAD * error * error,
    TURN_KP_MAX
);
```

**这项试验要配合非零基础 P。**如果把平方系数减小，却仍让基础 P=0，直道附近可能更软、回正更慢。

探索顺序：记录原运行参数；低速下令基础 P=1.0、D=0，使用上面的受限调度；如果跟线偏软、没有来回摆，再单独试 P=1.5、2.0。已经有验证过的非零基础 P 时，优先围绕原值小步比较，而不是必须重置成 1.0。

串口现有协议支持 `P1=1.0!`、`D1=0.0!` 这类指令。这里的 P1/D1 指方向参数，别和左右电机速度 PI 混在一起。若只是希望非常小的改动，也可以先保持原基础 P，把平方系数从 0.003 单独试到 0.002，再决定是否采用完整的受限方案。

这一步借鉴参考工程“根据误差情况改变增益”的思路，暂时不移植整套模糊规则。预瞄误差单位、周期和差速分配不一致时，参考车的 P、D 数字没有直接可比性。

### 5.4 前瞻怎么调，才不和环岛晚转互相打架

当前前瞻通常是 50、52、54 行：

| 现象 | 可单独比较的参数 | 需要盯住什么 |
| --- | --- | --- |
| 普通急弯发现太晚，远处线可靠 | `PROSPECT_LINE`：50 → 45 | 是否更早响应；远处中线是否跳动 |
| 远处中线噪声很大、提前切弯 | 50 → 55 | 是否变稳；是否因此赶不上急弯 |
| 仅环岛准备阶段转早 | 优先第 4 节；必要时只为状态 1 设置更近前瞻 | 不改变普通弯道的前瞻 |

行号越小看得越远。看近并不天然更丝滑，看远也不天然更好。

如果第 4 节处理后仍需要“只让环岛状态 1 看近”，可把前瞻函数中的那一行替换为：

```c
prospect_y = (ring_state == 1) ? 60 : (int16)PROSPECT_LINE;
```

保留后面的边界和有效行检查。60 只是候选值。状态切换会把名义前瞻从 60 跳回 50，也可能导致误差变化；不要与路线偏移、P/D 在同一轮一起改，长期应让名义前瞻逐帧缓变，并在有效性不足时立即服从有效行约束。

## 6. 出弯进直道抖：按信号先后顺序排查

### 6.1 先看中线/前瞻是不是先跳了

当前误差函数存在两个切换：

1. `search_end_line` 逼近名义前瞻时，前瞻被推到 `search_end_line + 1`。
2. 选定的三行全无效时，从第 13 行开始向下找第一条有效中线；这可能突然改用很远的一行。

因此中线截止位置或补线模式一变，实际取样位置就可能跳，不能把这种输入变化全归咎于 PID。

普通弯道还会经过 `cut_mid_line_by_slope_jump()`：相邻中线块的横向变化反号且差值超过阈值时，会清掉远段并改变 `search_end_line`。要看它是否误切了真实的弯道到直道连接处；不要先全局关闭，关闭后也可能把错误折线喂给控制。

### 6.2 一个可局部替换的视觉改法：优先找目标行附近的有效行

如果日志显示单行回退经常让取样位置远跳，在 `find_mid_line_lookahead_error()` 的局部变量区增加：


把整个 `if(valid_count == 0) { ... }` 替换为：

```c

    /* 按距离当前目标行由近到远搜索；同距离优先靠近车的一行。 */
    for(radius = 0; radius < (int16)MT9V03X_H; radius++)
    {
        for(side_try = 0; side_try < 2; side_try++)
        {
            if(radius == 0 && side_try == 1)
            {
                continue;
            }

            candidate_y = (side_try == 0)
                        ? (int16)(prospect_y + radius)
                        : (int16)(prospect_y - radius);

            /* 必须先验证行号，再访问数组。 */
            if(!mid_row_valid_at(candidate_y))
            {
                continue;
            }

            middle_x = mid_line_list[candidate_y];
            if(middle_x < 1 || middle_x >= MT9V03X_W - 1)
            {
                continue;
            }

            lookahead_valid_count = 1;
            last_lookahead_error = (int16)middle_x - (int16)MID_W;
            return last_lookahead_error;
        }
    }

    /* 全图都没有可用行，仍沿用原来的保留误差行为。 */
    return last_lookahead_error;
}
```

它只减少“回退选了离目标很远的点”这类跳变，不能修复错误中线，也没有解决所有丢线问题。后续可限制搜索半径、给低质量回退单独降速，但要配合明确的数据失效策略。

**当前源码里 `car_start()` 的持续丢线停车分支被注释掉了。**所以不能声称“无效 5 帧就一定停车”，也不能认为把 `LOOKAHEAD_MIN_VALID_ROWS` 从 1 改到 2 就能自动完成误差拒收和停车。它目前主要影响线路标志；相关运行逻辑需要另行接好。

### 6.3 当前出弯时，内轮目标可能一下涨很多

现在的差速比例是：

```text
外轮目标 = base_speed × (1 + 0.10 × |turn|)
内轮目标 = base_speed × (1 - 0.95 × |turn|)
```

基础速度 230 时：

| 状态 | 外轮目标 | 内轮目标 | 两轮平均目标 |
| --- | ---: | ---: | ---: |
| `abs(turn)=1` | 253 | 11.5 | 132.25 |
| `turn=0` | 230 | 230 | 230 |

单位都是当前代码换算下的 cm/s。

因此代码已经有“转得越多，平均目标越低”的效果；不能说完全没有弯道减速。问题是它**没有独立的基础速度规划和出弯缓升速**：差速一消失，平均速度目标也立即回升。

如果 `pid_error` 平稳回零，但内轮目标突然上升、实测速度随后反复摆，先处理目标变化和速度 PI。不要继续给视觉误差加越来越重的滤波。

### 6.4 D 项怎么改：只给方向环加明确的微分滤波

当前 `PID_Position()` 用的是“本次误差减去混合过的历史误差”，并不是独立、可调的一阶 D 滤波。D 默认是 0 时，它本身也不会造成 D 放大噪声；先确认运行中的 `NUM1.angle_d`。

若需要 D 帮助出弯回正，建议先只改方向环，不改电机速度 PI 共用的增量函数。

**第一步：**在 `Motor.c` 文件级静态变量区新增：

```c
static uint8 turn_pd_ready = 0;
static float turn_last_error = 0.0f;
static float turn_d_filtered = 0.0f;

#define TURN_D_ALPHA 0.50f
```

**第二步：**在 `Motor_Stop_And_Reset()` 内追加以下复位，原有停车和 PID 复位保留：

```c
turn_pd_ready = 0;
turn_last_error = 0.0f;
turn_d_filtered = 0.0f;
```

**第三步：**在 `Turn_PID_Control()` 局部变量区新增 `float d_raw;`，保留 Kp/Kd 的赋值，把原来的：

```c
pid_output = PID_Position(&image_pid, error);
```

替换为：

```c
if(!turn_pd_ready)
{
    /* 第一次拿到本次运行的误差时播种历史，避免凭空产生启动 D。 */
    turn_last_error = error;
    turn_d_filtered = 0.0f;
    turn_pd_ready = 1;
}

d_raw = error - turn_last_error;
turn_last_error = error;
turn_d_filtered += TURN_D_ALPHA * (d_raw - turn_d_filtered);

/* 仅方向环用 PD；当前方向环本来就没有生效的积分控制。 */
image_pid.Error = error;
image_pid.Out_P = error;
image_pid.Out_D = turn_d_filtered;
image_pid.LastError = error;

pid_output = image_pid.Kp * error
           + image_pid.Kd * turn_d_filtered;
```

D 可以从 0 → 0.5 → 1.0 做单变量比较；数值只是低速起点。这里仍是“每次 20 ms 更新的误差差分”，没有除以秒，不能直接搬使用 `de/dt` 的控制器增益。`TURN_D_ALPHA` 越小，滤波越重、延迟越大；不建议一上来就试 0.1。

图像是另一核异步更新的。实际图像处理帧率不足时，20 ms 外环可能重复读到旧误差，之后再收到新误差；上面的 D 滤波只能缓和这种现象。长期更稳的做法是发布带帧号/时间戳的一致视觉结果，让 D 按新帧和实际间隔计算，但这涉及共享数据协议和重新调 D，本文不把它冒充成几行已完成的移植。

### 6.5 如果主要是出弯突然提速，先限制两轮平均目标的上升

这是和 D 滤波分开的可选改动。它保留原来的左右轮速度比例，只让平均目标速度缓慢上升；需要减速时立即跟随原始目标。相比逐个轮子各加一个很慢的限速器，它不会额外改变计算出来的左右轮目标比例。

**第一步：**在 `Motor.c` 文件级静态变量区新增：

```c
static float turn_mean_speed = 0.0f;
#define TURN_MEAN_UP_STEP 4.0f  /* 每20ms增加4cm/s，约200cm/s^2 */
```

**第二步：**在 `Motor_Stop_And_Reset()` 内新增：

```c
turn_mean_speed = 0.0f;
```

**第三步：**在 `Turn_PID_Control()` 的局部变量区新增：

```c
float mean_raw;
float speed_scale;
```

在原有左右轮 `target_l/target_r` 全部算完之后、两个 `Motor_Set_Target()` 调用之前插入：

```c
/* 当前差速比例产生非负目标；先沿用原有的非负约束。 */
target_l = limit_more_than0(target_l);
target_r = limit_more_than0(target_r);
mean_raw = 0.5f * (target_l + target_r);

if(mean_raw > turn_mean_speed)
{
    turn_mean_speed = Limit_float(
        0.0f,
        turn_mean_speed + TURN_MEAN_UP_STEP,
        mean_raw
    );
}
else
{
    /* 减速不额外等待这层斜坡。 */
    turn_mean_speed = mean_raw;
}

if(mean_raw > 0.001f)
{
    speed_scale = turn_mean_speed / mean_raw;
    target_l *= speed_scale;
    target_r *= speed_scale;
}
```

原来的两个 `Motor_Set_Target()` 调用保留。以上新增状态从 0 开始，因此起步也会缓慢提速；基础速度 180、直行时，名义上约 0.9 秒升到目标。若起步过慢，可单独试每周期 6 cm/s。上面的加速度都是目标的变化率，不保证实测速度完全一致。

这个方案针对“出弯平均目标速度猛增”。如果需要大幅反向转向，两轮目标仍可能互换，不能声称它已经限制了所有单轮阶跃。若主要问题是横向反复摆，而平均速度并未突升，先回到误差、D 和路线交接排查。

### 6.6 如果差速指令仍阶跃，再单独试差速变化率限制

先不要同时叠“误差低通、D 低通、差速限速、轮速限速”。每多一层，急弯和反向弯的响应都有可能变慢。

下面的差速变化率限制是可选方案，用来比较“目标变化太快”的影响。

在 `Motor.c` 文件级新增：

```c
static float turn_cmd = 0.0f;
#define TURN_CMD_STEP 2.0f    /* 每20ms；默认关闭限制，后续单独试0.50f */
```

在 `Motor_Stop_And_Reset()` 内新增：

```c
turn_cmd = 0.0f;
```

在 `Turn_PID_Control()` 内，已有 `turn = Limit_float(...);` **之后**、`magnitude = ...;` **之前**插入：

```c
turn_cmd += Limit_float(-TURN_CMD_STEP,
                         turn - turn_cmd,
                         TURN_CMD_STEP);
turn = turn_cmd;
```

`turn` 的范围是 -1～1。步长 0.5 时，0 → 1 需要两次更新；+1 → -1 需要四次更新。目标更新周期是 20 ms，所以它是明确的响应时间代价，不是免费消抖。

先对比关闭限制的 2.0 和 0.5。只有目标仍过猛、且急弯/反向弯跟得上，才考虑 0.25。**如果出弯反而拖着不回正或 S 弯跟不上，应增大步长或撤掉这一层，而不是继续把它调小。**停车仍走原来的立即清 PWM 路径，不通过慢慢归零实现。

这种做法同时影响差速和平均目标回升。如果你希望“方向可以快速回正，但速度稍后再恢复”，优先比较第 6.5 节；仅对固定的 `base_speed` 做斜坡不够，因为差速回零本身也会让平均目标上升。长期可用可信的弯道形状规划基础速度，并对最终平均目标的恢复做约束。不能仅凭一次 `abs(pid_error)` 小就判为直道，因为车辆在弯中跟得准时误差也可能很小。

### 6.7 什么时候才轮到调电机速度 PI

| 波形先发生了什么 | 更应该改哪一层 |
| --- | --- |
| 中线或实际前瞻位置先跳，`pid_error` 跟着跳 | 视觉、选边、前瞻回退 |
| `pid_error` 平稳，但 `turn` 突然饱和/反号 | P 调度、D、差速输出 |
| 左右轮目标先跳，实测速度随后摆 | 目标变化率、出弯速度恢复 |
| 两轮目标都平稳，只有某个轮子的实测速度/PWM 持续振荡 | 该轮速度 PI、编码器反馈或机械响应 |

最后一种情况下再分别调左右轮：保持目标速度和另一侧参数不变，围绕当前运行值把 P 或 I 每次降低约 10% 做比较。如果降低 P 后跟踪明显迟缓，就回退；不能无条件把两侧 P/I 一起砍半。

## 8. 实际调车按这个顺序，每轮只动一组

| 轮次 | 操作 | 通过标准/下一步 |
| --- | --- | --- |
| 0 | 保存当前运行参数和一段原始日志，分别记录普通急弯、左环、右环、出弯直道 | 先知道误差、状态、来源、轮速谁先变化 |
| 1 | 基础速度 230 → 180，其他不改 | 判断是否主要受速度影响 |
| 2 | 完成第 4.2 节：状态 1 固定外侧半宽路线 | 状态 1 中线不再主动朝岛内大幅偏；接管失败也有记录 |
| 3 | 若状态 2 仍进早，`RING_S1_TOP_B` 每次加 5；检查是否是无点的 127 误触发 | 入环位置后移且左右环都能正常进状态 2 |
| 4 | 按实际补线来源，短边 0.65 → 0.70，或长边 0.75 → 0.70 | 中线外移、实车间距改善，不频繁换源 |
| 5 | 若普通急弯仍突然满差速，试受限 P 调度；保持 D=0 | 误差下降，满差速比例降低，同时还能完成急弯 |
| 6 | 若取样位置跳，先改第 6.2 节的回退；需要时再小量增加 D | 误差和回正过程更连续，没有增加细抖 |
| 7 | 平均目标速度出弯猛增时，试第 6.5 节每周期 +4 cm/s 的平均速度缓升 | 恢复速度更连续，左右目标比例保留 |
| 8 | 仅有差速指令阶跃证据时，试 `TURN_CMD_STEP`：2.0 → 0.5 | 出弯更平顺，急弯和反向弯不拖慢到跟不上 |
| 9 | 低速稳定后，基础速度每次增加 10～20 cm/s | 每次都重新检查环岛进出点和出弯速度恢复 |

每个场景尽量重复 3 次；一次顺了不代表稳定。若变差，恢复本轮之前的那一组参数，别再同时补改三个参数。

## 9. 建议记录哪些量，才能调得明白

现有串口已有左右轮目标/实测速度、PWM、`pid_error` 等。建议在主循环发送的调试快照里补以下量，不要在控制中断里打印长串口数据：

| 量 | 用途 |
| --- | --- |
| 图像帧号、帧间隔 | 判断真实处理帧率及控制是否重复使用旧误差 |
| `ring_state`、`ring_started`、`ring_confirm` | 判断早转发生在状态 1 还是切入状态 2 时 |
| `ring_short_side`、真实短边 top、左右点数 | 判断方向锁定、门槛和 127 无点情况 |
| 最终中线来源、接管成功/失败 | 判断到底哪个偏移参数生效 |
| `road_mode`、`search_end_line` | 判断是否切补线或切掉了远段 |
| 实际前瞻行、是否用了单行回退、`lookahead_valid_count` | 判断误差是否来自不稳定采样位置 |
| 原始误差、`turn_kp_used`、D 分量、限幅前后 `turn` | 判断 P 饱和、D 踢动、差速变化率 |
| 左右轮目标、实测速度、PWM | 区分路线问题、目标阶跃和电机跟踪振荡 |

这些新增观测量需要在产生结果的一侧更新，再以一致快照发布，避免把不同时刻的状态拼成一帧“假日志”。日志增加后也要确认没有明显拖低图像处理帧率。
