# 2026 霹雳火：差速控制 + 增量式 PID 调参总结

> 依据源码：`霹雳火2026工程代码(1)/thunderbolt-fire-2026-20260715-70绕行`（`driver/Motor.cpp`、`MENU.cpp`、`main.cpp`）
> 配合参考：`霹雳火2025电机PID调参参考.md`（TC264 例程，在线调参指令）
> 面向对象：TC264 控制位（转向环 + 速度环），白话 + 数字全部可追溯。

---

## 0. 一句话速览

这辆车是**两层闭环**：外层转向环（10ms）负责"该往哪拐"，把拐弯强度换算成**左右轮目标速度**（差速）；内层速度环（2ms，增量式 PI）负责"分别把每个轮子追到目标速度"。**调增量式 PID 调的就是内层速度环。** 差速本身没有 PID——它只是转向环输出的一种分配公式。

```
摄像头偏差 image_bias
        │ 10ms
        ▼
转向环 TurnControlNew（PD，可接模糊）
        │ 输出"转向强度" pid_val
        ▼
差速分配（内轮×0.95 狠减、外轮×0.10 微加、钳 0）
        │ ENCO_Wish_L / ENCO_Wish_R
        ▼
2ms 速度环（增量式 PI，左右各一套）
        │ PWM（限幅 ±8000）
        ▼
电机 → 编码器 → 实际速度（反馈回速度环）
```

## 1. 差速控制：转向环输出是怎么变成左右轮速度的

### 1.1 代码位置

`driver/Motor.cpp:454` → `void MotorDriver_TurnControlNew(float bias)`，每 10ms 调用一次（`main.cpp:158` 注释"转向控制定时器回调（10ms 周期）"，`main.cpp:337` 注册）。

调用方式（`main.cpp:165-175`）：巡线时 `TurnControlNew(image_bias)`；YAW 绕行时 `TurnControlNew(yaw_error * YAW_BIAS_GAIN)`。也就是说**不管是循迹还是绕行，最终都走同一个差速函数**——这是"方案D：全程 TurnControlNew 统一控制源"的设计。

### 1.2 逐行拆解（Motor.cpp:454-489）

```c
void MotorDriver_TurnControlNew(float bias) {
    static float last_error = 0.0f;

    float error = bias;                          // ① 偏差（±20，视觉队友给）
    float Kp = turn_pid_new.Kp;                  // ② 基础 Kp = 1.52
    float Kd = turn_pid_new.Kd;                  //    基础 Kd = 10.4

    Kp = Fuzzy_P(error, (error - last_error), Kp);  // ③ 模糊修正 Kp（当前不用可去掉）
    Kd = Fuzzy_D(error, (error - last_error), Kd);  //    模糊修正 Kd

    ec = error - last_error;                     // ④ 误差变化量（微分输入）
    ec = Limit(ec, -3.0f, 3.0f);                 //    ★ ec 限幅 ±3，防跳变打爆 D

    float pid_val = (Kp * error + Kd * ec) / 20.0f; // ⑤ 转向强度 = (PD 输出)/20

    if (pid_val > 0.0f) {                        // ⑥ 需要"往一侧拐"（符号见下）
        encoder_left_wish  = (int16_t)((1.0f - pid_val * 0.95f) * base_speed);
        encoder_right_wish = (int16_t)((1.0f + pid_val * 0.1f)  * base_speed);
        if (encoder_left_wish < 0) encoder_left_wish = 0;   // ★ 内轮钳 0，不许反转
    } else {                                     //    对称的另一边
        float radian = -pid_val;
        encoder_right_wish = (int16_t)((1.0f - radian * 0.95f) * base_speed);
        encoder_left_wish  = (int16_t)((1.0f + radian * 0.1f)  * base_speed);
        if (encoder_right_wish < 0) encoder_right_wish = 0;
    }
}
```

### 1.3 四个设计点的白话解释

| 设计点 | 数值 | 为什么 |
|---|---|---|
| `pid_val = (Kp·e + Kd·ec) / 20` | 除以 20 | 把 PD 输出归一化成"差速比例"。偏差满幅 ±20 时，`pid_val` 大约落在 ±3 左右，直接乘到速度上就是 0~±3 倍的加减 |
| `ec = Limit(ec, ±3)` | ±3 | 偏差跳帧（摄像头掉帧/换赛道）时 D 项瞬间巨大，限幅后转向不会"抽风" |
| 内轮 × `0.95`（狠减） | 0.95 | 拐弯主要靠**内侧轮减速**：内轮减到 0 时车几乎原地转 |
| 外轮 × `0.10`（微加） | 0.10 | 外侧只微加速：保证外侧有速度、车不甩尾，又不像对称差速那样把平均速度推太高 |
| 内轮钳 0 | `<0 → 0` | 内轮最低停转，**禁止反转**（除非 YAW 绕行阶段，见速度环反接制动） |

> 平均速度的一个隐藏特性：左右轮相加 = `(2 − 0.85·pid_val)·B`，**偏差越大平均速度越低**——也就是说这套差速天然"急弯自动减速"，不需要额外的弯道降速逻辑。这是内轮 0.95 > 外轮 0.10 的结果。

### 1.4 和 2025 TC264 例程的差速对比

| | 2026（本工程） | 2025（TC264 例程） |
|---|---|---|
| 内轮系数 | 0.95 | xishu_down = 0.90 |
| 外轮系数 | 0.10 | xishu_up = 0.15 |
| 归一化 | `/20`（偏差 ±20 量纲） | `×0.01`（像素偏差量纲） |
| 内轮钳 0 | 有 | 有（隐含在 `limit_more_than0` 类处理） |

数字不同是因为**偏差量纲不同**（2026 是 ±20 归一化偏差，2025 是像素偏差）。移植时注意：系数按你的偏差量纲重新标定，别直接抄。

## 2. 增量式 PID：2ms 速度环实现拆解

### 2.1 代码位置

`driver/Motor.cpp:323-416` → `MotorDriver_LeftPidControl` / `MotorDriver_RightPidControl`，每 2ms 调用一次（`main.cpp:341`：`motor_timer.init_ms(2, motor_callback)`）。左右轮**各自独立**的静态状态（`s_left_error/s_left_lastError/s_left_pwm` 等），互不干扰。

### 2.2 核心公式（左轮，右轮对称）

```c
s_left_error  = encoderWish - encoderTrue;            // ① 误差 = 目标 - 实际
i_out         = motor_pid.Ki * s_left_error;          // ② 积分项（单步）
s_left_pwm   += motor_pid.Kp * (s_left_error - s_left_lastError) + i_out;  // ③ 增量式！
s_left_lastError = s_left_error;                      // ④ 存下本帧误差

// ⑤ 输出限幅 ±8000
s_left_pwm = (s_left_pwm > SPEED_PWM_MAX) ? SPEED_PWM_MAX : s_left_pwm;
s_left_pwm = (s_left_pwm < SPEED_PWM_MIN) ? SPEED_PWM_MIN : s_left_pwm;
```

**增量式**：`Δpwm = Kp·(e − e_last) + Ki·e`，然后 `pwm += Δpwm`。每次只加一个"变化量"，不是每帧重算绝对值——所以天然平滑、天然抗积分饱和、目标速度切换时不跳变。

### 2.3 参数与三个保护（Motor.cpp:309-347）

```c
motor_pid = { Kp=100, Ki=5, Kd=0 }   // Motor.cpp:87，注释："Kp 80→100 加速弯道减速响应"
#define ENCODER_START_THRESHOLD 10   // 编码器启动阈值：实际速度小于 10 视为静止
#define DEADZONE_PWM 800             // 电机死区补偿：启动瞬间 PWM 抬到 800 才能推动电机
// 输出限幅 [SPEED_PWM_MIN, SPEED_PWM_MAX] = [-8000, 8000]
```

| 机制 | 条件 | 动作 | 为什么 |
|---|---|---|---|
| 输出限幅 | `pwm > 8000 / < -8000` | 钳到 ±8000 | 兜底保护，防止 PID 爆表 |
| 死区补偿 | `encoderWish>0 && encoderTrue<10 && pwm>0 && pwm<800` | `pwm = 800` | 电机有死区：PWM 太小推不动。只在"启动瞬间"生效，正常运行时不管 |
| 反接制动 | `!g_yaw_active && encoderWish<=0 && encoderTrue<=0 && pwm<0` | `pwm = 0` | 目标≤0 且已经在停/反转时，把负 PWM 钳 0，防止车子倒溜反转。**YAW 绕行阶段跳过**（`g_yaw_active`），因为绕行需要内轮主动反转原地转 |

### 2.4 ResetSpeedPID：什么时候调用、为什么

`MotorDriver_ResetSpeedPID()`（Motor.cpp:625）调用左右轮的 Reset，**绕行 YAW 阶段切换差速时调用**（注释：清除旧巡线的积分惯性，使新 encoder_wish 立即生效）。

白话：增量式 PID 的 `s_pwm` 是"累加出来的记忆"。巡线时内轮 PWM 可能积累得很低，突然切换到绕行要求它加速——如果不清零，旧的积分惯性会让新目标反应慢半拍。**切换方案前清一次 PID 状态**，这是增量式 PID 特有的坑。

## 3. 2026 vs 2025：速度环参数对照（TC264 移植参考）

| 项 | 2026（龙芯工程） | 2025（TC264 例程） |
|---|---|---|
| Kp | 100 | 70 |
| Ki | 5 | 3.5 |
| Kd | 0（只用 PI） | 0（只用 PI） |
| 积分项限幅 | 无单独限幅（靠输出限幅兜底） | `I_out 限幅 ±Ki×65`（更讲究） |
| 输出限幅 | ±8000 | ±10000（实际 PWM 上限 8000） |
| 反馈滤波 | 未见（龙芯侧另有处理） | 二阶滞后滤波 `0.2/0.4/0.4` |
| 反馈量纲 | encoderTrue 直接用 | 传 `2×encoder_data`（与目标同量纲） |

**移植建议**：TC264 上直接用 2025 的结构（有 I 项限幅、有滤波），Kp/Ki 从 `70 / 3.5` 起步，比 2026 的 `100 / 5` 更稳；觉得弯道减速响应慢再往 100/5 靠。

## 4. 怎么调：在线调参机制 + 调参顺序

### 4.1 调参入口（不用改代码、不用重新编译）

**2026 工程（LCD 菜单）**：

- 菜单 21 `Motor_Turn_PID_show()`（MENU.cpp:591）——调**转向环**：`Turn_Kp1`(Kp)、`Turn_Kd`、`Turn_Ki`、`Turn_Kp2`、`Turn_step`（步长按键切换：`0.1 → 0.05 → 0.01 → 0.005 → 1`）。Enter = 发车并写参数，Return = 保存返回。
- 菜单 22 `Motor_PID_show()`（MENU.cpp:665）——调**速度环**：`motor_P`(Kp)、`motor_I`(Ki)、`in_rad/out_rad`、`FUYA PWM`、`Motor_step`（步长：`0.01 → 0.1 → 1 → 10`）。

按键 `+/-` 直接改，改了立刻生效，按 Enter 发车实测——这就是"怎么调"的物理入口。

**2025 TC264 例程（串口/逐飞助手）**：支持在线指令，格式如 `P1=70!`、`I1=3.5!`（P1/I1 代表 1 号即左电机，具体通道号见你工作区的《霹雳火2025电机PID调参参考.md》）。数值改完立即生效，配逐飞助手示波器看波形。

### 4.2 调参顺序（一步一个变量）

1. **先确认方向与量纲**：目标增大 → 实际速度必须增大。方向反了先把编码器取负或对调 Wish。注意 2025 例程反馈传的是 `2×encoder_data`，量纲和目标必须一致。
2. **只留 P**（Ki=0）：Kp 从 50~70 起步。给车一个阶跃（发车/加减速），看实际速度追目标的速度：
   - 追得慢、滞后大 → 升 Kp；
   - PWM 抖动、电机嗡嗡响、速度波形毛刺 → 降 Kp。
3. **加 I**：Ki 从 1~3.5 起步。I 的作用是磨掉"始终差一点"的静差（比如上坡、负载变化）。
   - 启动瞬间猛冲/过冲震荡 → 降 Ki（或加积分限幅）；
   - 直道蛇形游走 → I 太大，降；
   - 目标到了但差一口气追不平 → 升 Ki。
4. **弯道验证**：入弯减速响应慢 → 升 Kp（2026 注释就是干这个的："Kp 80→100 加速弯道减速响应"）；出弯回摆 → 检查 I 是否过大。
5. **左右轮分开看**：直线跑偏但方向没错 → 左右轮响应不一致，先机械（轮胎/重心）再参数（左右 Kp 微调，2025 例程默认左右对称 70/3.5）。

### 4.3 症状 → 调法速查表

| 现象 | 首选调整 |
|---|---|
| 速度追不上目标、加速肉 | ↑ Kp（或 ↑ 滤波系数里的"新值占比"） |
| PWM 抖动/电机嗡嗡/速度震荡 | ↓ Kp（检查编码器滤波是否太轻） |
| 启动瞬间冲一下 | ↓ Ki（或加积分限幅） |
| 直道蛇形、来回摆 | ↓ Ki（或 ↓ Kp） |
| 目标差一点点始终追不平 | ↑ Ki |
| 弯道内轮 PWM 常年在 0 附近 | 差速系数/转向环的事，不是速度环问题 |
| 切换方案后响应慢半拍 | 调用 `ResetSpeedPID()` 清积分惯性 |

## 5. 移植到 TC264 的拼装清单（你现在的位置）

1. **转向环**：把 `TurnControlNew` 的逻辑搬进 2025 的 `turn_pid()`（8ms）。偏差接口用 `image_bias`（±20），`/20` 归一化保留；`ec` 限幅 ±3 保留；差速系数按你实际偏差量纲标定（起步可先抄 0.95/0.10）。
2. **速度环**：直接用 2025 的 `motorL_pid()/motorR_pid()`（增量式 PI + I 项限幅 + 二阶滞后滤波），起步 `Kp=70, Ki=3.5`。
3. **接口**：`encoder_left_wish/encoder_right_wish`（2026）↔ `ENCO_Wish_L/ENCO_Wish_R`（2025），一个意思，改个名。
4. **保护**：死区补偿、输出限幅、反接制动（YAW 时跳过）——2025 例程里死区/限幅已有，反接制动逻辑按需补。
5. **在线调参**：TC264 用逐飞助手串口指令（`P1=70!` 类），上车边跑边调。
