TC264 双定时器中断执行时序（示意）

两个 ISR 均挂在核 0（IFX_INTERRUPT 第 2 参数 = 0）→ 单核串行 + 嵌套抢占；图中 ISR 块宽度为示意，假设单次执行约 1ms，真实耗时取决于函数体。

关键结论

  • 不是并行执行：IFX_INTERRUPT(名字, 0, 优先级) 第 2 个参数是核 ID，两个 ISR 都写在 0 → 都挂在 CPU0。单核同一时刻只能执行一条指令流，两个 ISR 只能“排队 + 互相嵌套”，不可能真正同时跑。
  • 嵌套是怎么开的：进 ISR 时硬件自动把当前优先级 CCPN 设为该中断的优先级（挡住同级/低级），而你的 ISR 第一行 interrupt_global_enable(0) 把 CCPN 清零 → 门全开，任何 pending 的中断都能立刻抢占当前 ISR。
  • 5ms 与 10ms 在 0 / 10 / 20 / 30 / 40ms 碰撞：此时两个请求同时 pending，硬件按优先级仲裁（TriCore 数值越大越优先，具体取 CCU6_0_CH0_ISR_PRIORITY / CH1_ISR_PRIORITY 的值）——高优先级先进门，低优先级随即嵌套进去先跑完，高优先级再收尾。观察上二者是“你插我、我插你”地串行完成。
  • 两个坑：① CH0 写编码器数据、CH1 读编码器数据做 PID，嵌套抢占时多字节结构体可能读到中间状态（32 位对齐变量在 TriCore 上读写原子，一般没事）；② 碰撞时刻 CH0 的扫描/启动耗时若太长，会把 CH1 的 10ms PID 节拍挤变形 → 控制周期抖动。惯例：控制环（PID）优先级 > 扫描/杂务优先级，ISR 里不干耗时活。
想要真正的“同时”（并行）：TC264 是双核，把其中一个 ISR 的核 ID 改成 1，如 IFX_INTERRUPT(cc60_pit_ch1_isr, 1, CCU6_0_CH1_ISR_PRIORITY) → 两个 ISR 各占一核真并行。代价：共享变量需核间互斥（临界区/原子操作），外设中断要配到对应核。结论：你现在的 5ms 扫描 + 10ms 控制写法，单核 + 嵌套完全够用，多数智能车代码就是这么写的。
